Session rail · states beyond the happy path

Builds on Session Rail v6 (pinned ticket header with meter strip, Plan / Agents / PR tiles). Dots now use the status-mark shapes from the component sheet: circle running, diamond failing, triangle needs attention, ring done, small dot not yet.

1 · Ticket header: linking and editing

The editor replaces the ticket block in place; the meter strip below never moves. Enter links, Esc cancels and restores. The branch-name suggestion is a chip (Tab focuses it, Enter accepts). Lookups run once; failures keep the editor open with the reason and one way forward. A linked ticket's ⋯ menu holds change, open, copy and unlink. Tickets are fetched once, so the only refresh affordance is Retry.

2 · Tiles: loading, stale and connector states

First load shows skeletons in the final layout, never "Loading". A failed refresh keeps the last good data in --muted ink (no opacity), adds a footer line with the age and Retry, and rings the tile --warn. Connector problems replace the PR tile's body with one sentence and one link. PRs refresh every 60s while the rail is visible and pause when it isn't; rate limits back off and say when the next try is.

3 · Thin rail (48px) and the toggle

The ▥ glyph becomes an icon button (right_panel_close / right_panel_open) with a tooltip and ⌘\. It switches 300 ↔ 48 over --dur-slow with --ease-out; content fades out in the first 80ms so nothing reflows mid-slide (instant under reduced motion). Windows under 1000px start thin. In the thin rail each tile is a button: shape + letter, an accessible name with the full sentence, a tooltip on hover and focus, and Enter opens the rail at that tile. Tile open/closed choices persist globally; "+n more" and done folds reset per session.
